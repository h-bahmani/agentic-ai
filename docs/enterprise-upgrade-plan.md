# نقشه ارتقای MobinAid: مدل GPU، تحلیل مستند، ایمیل و یادآوری

وضعیت: طرح اجرایی؛ اتصال GPU/Outlook و یادآوری در این سند به معنی پیاده‌سازی یا تأیید عملی آن‌ها نیست.

## ترتیب اجرا

1. ارزیابی پایه: مجموعه پرسش‌های مستقل و داده مرجع؛ ثبت خروجی نسخه فعلی و خطاهای فیلتر، جمع، تاریخ، واحد، گروه‌بندی و انتخاب ابزار.
2. قرارداد تحلیل: تعریف IR نوع‌دار شامل entity، metric، aggregation، filters، group_by، sort، limit، calendar/timezone و سطح دسترسی. مدل فقط پیشنهاد طرح می‌دهد؛ validator طرح را با metadata واقعی تطبیق می‌دهد. محاسبه، فیلتر، JOIN و رتبه‌بندی در executor قطعی انجام می‌شود. شرط ناشناخته موجب درخواست توضیح یا خطای روشن می‌شود، نه حذف شرط. الگوهای regex فعلی به‌تدریج با حفظ آزمون‌ها جایگزین می‌شوند؛ افزودن الگوی موردی راهبرد نهایی نیست.
3. ارائه‌دهنده GPU: adapter مستقل OpenAI-compatible با بررسی metadata و آزمون واقعی tool calling/structured output. انتخاب مدل پس از benchmark فارسی، تحلیل و ابزار؛ بدون دانلود خودکار. دامنه مجاز سرور دقیق، TLS/احراز هویت، timeout/cancellation و سقف concurrency؛ جایگزین‌کردن سیاست فقط-loopback با allowlist احرازشده، نه پذیرش URL دلخواه کاربر.
4. ابزارهای معنایی شرکت: ابزارهای گزارش سطح بالاتر برای aggregate/compare/ranking/absence با ورودی نوع‌دار و provenance؛ 46 ابزار موجود حفظ می‌شوند ولی برنامه برای هر پرسش schema مرتبط را عرضه می‌کند. دسترسی جدول/ستون/ردیف و نقش، پیش از اجرا اعمال می‌شود. نام ابزار و readOnlyHint به تنهایی مدرک مجازبودن نیست.
5. هویت سازمانی و ذخیره‌سازی: user/tenant isolation، نشست مستقل و repository در پایگاه اختصاصی agent؛ بدون migration روی جداول کسب‌وکار. تاریخچه، cache و نمایه ایمیل باید با هویت و مجوز همان کاربر کلیدگذاری شوند.
6. Outlook: ابتدا تعیین Microsoft365 یا Exchange داخلی. برای Microsoft365، Entra app registration و delegated OAuth، Mail.Read برای خواندن متن؛ بدون Mail.Send/Mail.ReadWrite در فاز اولیه. توکن خارج prompt/log/frontend و با ذخیره امن و لغو دسترسی؛ secret در کد یا چت قرار نمی‌گیرد. هیچ اتصال یا رضایت‌نامه کاربر خودکار دور زده نمی‌شود.
7. ایمیل: search/read/thread/attachments با کنترل نوع و حجم، pagination، delta sync و نمایش بازه/پوشش جستجو. پاسخ باید به پیام واقعی با subject/sender/time/message ID/link قابل بررسی متصل باشد. «پیدا نشد» با «وجود ندارد» یکسان نیست. HTML و متن ایمیل داده غیرقابل اعتمادند و اجازه اجرای ابزار ایجاد نمی‌کنند. نمایه محلی و semantic search در صورت نیاز، با رضایت نگهداری داده و عدم خروج داده از مقصد مجاز.
8. یادآوری: پیشنهاد عنوان، زمان دقیق و timezone، پیوند ایمیل و مقصد؛ ایجاد فقط پس از درخواست/تأیید مشخص کاربر. Microsoft To Do با Tasks.ReadWrite یا تقویم با مجوز مناسب، پس از انتخاب مقصد. reminderDateTime و isReminderOn فقط برای مقصدی که واقعاً پشتیبانی دارد. وظیفه زمان‌بندی پایدار، retry محدود، idempotency و پیگیری وضعیت؛ موفقیت فقط پس از ثبت واقعی و دریافت شناسه. زمان UTC ذخیره و با Asia/Tehran نمایش داده می‌شود؛ تاریخ شمسی باید صریح تبدیل و آزمون شود.

## مرز دقت

مدل بزرگ‌تر به‌تنهایی صحت تحلیل را تضمین نمی‌کند. عدد، واحد، مخرج نسبت، بازه، کامل‌بودن صفحات، NULL، tie، fanout و grain باید در قرارداد و اجرای برنامه کنترل شوند. مبلغ مالی با Decimal و انتقال بدون افت دقت نگهداری شود؛ نسبت‌دادن تومان/ریال بدون metadata ممنوع است. داده تأییدشده و تفسیر مدل جدا نمایش داده شوند. برداشت علّی از همبستگی یا تحلیل بدون داده کافی نباید به عنوان واقعیت صادر شود. بیرون از قابلیت تأییدشده باید صریحاً پاسخ نامطمئن/نیاز به توضیح اعلام شود؛ تضمین بی‌خطایی همه سؤال‌ها ادعا نمی‌شود.

## آزمون پذیرش

- مجموعه سؤال‌های جدید و پارافریزهای دیده‌نشده، نه فقط مثال‌های رفع‌شده؛ سنجش جداگانه دقت، پوشش، امتناع صحیح و امتناع اشتباه.
- تطبیق عدد با oracle مستقل روی fixture و سپس داده واقعی فقط‌خواندنی؛ جداکردن تست mock از integration واقعی.
- نمونه‌های empty/NULL/duplicate/ties، join fanout، فارسی/انگلیسی، تاریخ شمسی/میلادی، timezone و داده حین تغییر.
- قطعی GPU/MCP/Graph، timeout، لغو، نرخ429، صفحات ناقص، refresh token و قطع/لغو مجوز.
- عدم نشت ایمیل کاربر A به B؛ عدم تبدیل دستور داخل ایمیل به اختیار اجرایی؛ عدم ارسال ایمیل یا ساخت یادآوری ناخواسته/تکراری.
- ایجاد واقعی یادآوری آزمایشی فقط با اجازه مشخص، دریافت شناسه و بررسی زمان و بازیابی پس از restart.

## اطلاعات لازم پیش از اتصال

GPU: API base URL، پروتکل، نام مدل، نرم‌افزار سرویس، VRAM تخصیص‌یافته، دسترسی شبکه و روش احراز هویت.
ایمیل: Microsoft365/Exchange داخلی، tenant و سیاست Entra/تأیید مدیر، مدل دسترسی شخصی یا shared mailbox.
یادآوری: داخل MobinAid، To Do یا تقویم؛ سیاست زمان/تکرار/اعلان.
