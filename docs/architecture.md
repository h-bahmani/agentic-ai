# معماری و مسیر استقرار

## تصمیم معماری

یک برنامه مستقل FastAPI، frontend ساده با فایل‌های محلی، adapter Ollama، MCP SDK رسمی v1 و حلقه اجرای محدود. بیزنس‌لاجیک و PostgreSQL در سرویس موجود شرکت می‌مانند. یک درخواست فعال در هر process پذیرفته می‌شود تا حافظه مدل و ترتیب مکالمه کنترل شود؛ درخواست هم‌زمان 409 می‌گیرد.

جریان: مرورگر → API با کنترل Host/Origin/اندازه ورودی → بررسی نصب و metadata مدل → کشف ابزارهای مجاز → ارائه JSON Schema به مدل → اعتبارسنجی کل batch → اجرای متوالی MCP → ارسال نقش tool و داده نتیجه به مدل → پاسخ فارسی و شواهد مستقل UI. حداکثر فراخوانی و مهلت کل مستقل اعمال می‌شوند. retry عملیات وجود ندارد؛ اتصال تازه در درخواست بعدی برقرار می‌شود. HTTP محیطی proxy استفاده نمی‌کند. shell، SQL دلخواه، اجرای Python مدل و دانلود مدل endpoint ندارند.

تفکیک ماژول‌ها: `llm.py` قرارداد provider و Ollama؛ `mcp_client.py` transport و schema validation؛ `agent.py` حلقه؛ `storage.py` حافظه توسعه؛ `services.py` قراردادهای فاز ۲؛ `main.py` مرز HTTP. آینده OpenAI-compatible/vLLM باید قرارداد LLM را پیاده کند؛ tool execution به provider وابسته نیست.

فهرست مجاز ابزارها سیاست برنامه است، نه دستور مدل. SDK/schema/metadata به‌تنهایی مدرک read-only بودن نیستند؛ سیاست فعلی پس از بازبینی ابزارهای موجود شرکت انتخاب شده است. پیش‌فرض فعلی all_readonly شامل هر ۴۶ ابزار بازبینی‌شده شرکت است. درخواست ابتدا به گفت‌وگو/معرفی قابلیت/داده شرکت مسیریابی می‌شود؛ گفتگو و معرفی قابلیت بدون اتصال اجرای MCP پاسخ می‌گیرند. برای مسیر شرکت، ابزارهای مرتبط از فهرست کامل انتخاب و فقط schemaهای لازم به مدل داده می‌شود؛ اگر انتخاب اولیه مشخص نباشد یا بیش از ۵ ابزار باشد، مدل با کاتالوگ فشرده حداکثر ۴ ابزار را انتخاب می‌کند. نتیجه و فراخوانی ابزار قبلی به یک کار تازه منتقل نمی‌شود و تکرار فراخوانی یکسان در هر اجرا متوقف می‌شود. لاگ اجرای ابزار شامل نام، مدت و وضعیت است؛ prompt، آرگومان، credential و نتیجه در audit log ثبت نمی‌شوند. شواهد و گفتگو فقط در حافظه کاربر محلی هستند. خطای اجرای ابزار، نبود مدل، ظرفیت context و timeout به‌صورت کد/پیام نمایش داده می‌شوند.

## مدل‌ها

Qwen3:4b فعلاً مدل توسعه انتخابی کاربر است. صفحه رسمی Ollama برای artifact فعلی اندازه حدود 2.5GB و quantization Q4_K_M را گزارش می‌کند؛ این اندازه فایل است، نه RAM لازم. ظرفیت واقعی RAM/VRAM، KV cache و هم‌زمانی باید روی ماشین اندازه‌گیری شوند. کوچک بودن تضمین دقت فارسی یا انتخاب درست ابزار نیست. این برنامه هیچ API pull ندارد؛ نصب کامل و metadata را پیش از inference بررسی می‌کند. Ollama ممکن است مدل نصب‌شده را هنگام درخواست بارگذاری کند و خطای کمبود حافظه باید شکست قابل نمایش باشد، نه نصب مدل دیگر.

ادعای «بهترین مدل» بدون مجموعه آزمون دامنه شرکت قابل دفاع نیست. معیار جایگزینی: صحت ابزار و آرگومان، پاسخ فارسی مستند، عدم اختراع اعداد/واحد پول، latency، حافظه و دقت چندمرحله‌ای. پرسش‌های count، revenue بدون واحد پول، مقایسه، خطای سرویس و prompt injection را روی داده تست‌شده بسنجید. امتیاز تبلیغاتی مدل جای پذیرش شرکت نیست.

## فاز ۲

پیاده‌سازی repository در پایگاه مستقل agent با credential جدا؛ migration فقط پس از تأیید. اتصال STT به Whisper موجود از طریق یک سرویس مالک مدل برای جلوگیری از بارگذاری تکراری؛ upload ID کنترل‌شده، محدودیت حجم/نوع، مسیر مجاز، پاک‌سازی و محتوای صوتی. Piper تنها بعد از تأیید voice فارسی و مجوز/کیفیت؛ vision، OCR و image generation سرویس‌های مجزا. تا آماده‌شدن backend، قابلیت باید unavailable بماند. هویت سازمانی OIDC، policy نقش‌ها و تأیید عملیات حساس با اتصال دقیق user/tool/arguments لازم است؛ در فاز فعلی این عملیات بسته‌اند.

## فاز ۳ / A40

تخصیص GPU باید توسط شرکت مشخص شود. نام A40 به‌تنهایی ظرفیت آزاد را تعیین نمی‌کند؛ VRAM اختصاص‌یافته، quantization، طول context، KV cache و تعداد درخواست هم‌زمان را اندازه بگیرید. vLLM روی Linux مورد پشتیبانی، server OpenAI-compatible و مدل دارای template ابزار مناسب؛ قرارداد provider را پیاده و آزمون schema/tool-call را تکرار کنید. مدل بزرگ‌تر فقط پس از benchmark و تأیید دانلود/مجوز.

مرز شبکه: gateway پشت reverse proxy با TLS و OIDC؛ inference و MCP روی شبکه خصوصی allowlisted. secret manager و credential سرویس جدا، timeout، quotas، صف، concurrency و rate limit به تفکیک کاربر؛ audit append-only با حداقل محتوا و trace IDs. چند worker فقط بعد از repository مشترک و distributed locking/queue. readiness/liveness جدا و metrics latency/errors/token/memory بدون متن حساس. container image قفل‌شده و بررسی وابستگی‌ها؛ مدل‌ها و imageها از mirror شرکت به محیط آفلاین منتقل شوند. برای conversation DB و config سیاست retention، رمزگذاری، backup و آزمون restore لازم است. هیچ migration روی business DB خودکار انجام نمی‌شود.

## منابع رسمی بررسی‌شده، 2026-11-16

- Ollama chat API: https://docs.ollama.com/api/chat — ابزارها، نقش پیام، options، think و keep_alive.
- Qwen3:4b artifact: https://ollama.com/library/qwen3:4b — مشخصات مدل توسعه.
- MCP Python SDK v1: https://github.com/modelcontextprotocol/python-sdk/tree/v1.x — برای محیط موجود SDK 1.30.0 و `streamablehttp_client(..., httpx_client_factory=...)`؛ امضای نصب‌شده نیز مستقیم بررسی شد. مستندات main اکنون به نسل جدید SDK اشاره می‌کنند؛ به‌روزرسانی کورکورانه انجام نشده است.

دانلود یا نصب هیچ مدل/بسته‌ای در این اجرا انجام نشده است.
