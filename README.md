# دستیار سازمانی محلی — فاز ۱

این برنامه در پوشه‌ای مستقل ساخته شده و فایل‌های MyLocalAgent، LM Studio، Ollama، MCP شرکت و جداول PostgreSQL را تغییر نمی‌دهد. به LM Studio وابسته نیست. اجرای مدل و ابزار واقعی است؛ آزمون‌های واحد از doubles صریح استفاده می‌کنند.

## اجرای Windows

ابتدا Ollama و سرویس‌های موجود شرکت را روشن کنید. اجرای برنامه هیچ بسته یا مدلی نصب نمی‌کند. Python انتخابی باید وابستگی‌های `backend/requirements.txt` را **از قبل** داشته باشد. محیط فعلی CompanyMicroApiTest این وابستگی‌ها را دارد و فقط برای اجرای برنامه استفاده می‌شود؛ تغییری در آن داده نمی‌شود.

از ریشه مخزن:

```powershell
.\enterprise_agent\scripts\start.ps1 -Python 'D:\CompanyMicroApiTest\.venv\Scripts\python.exe'
```

سپس [رابط فارسی محلی](http://127.0.0.1:8570) را باز کنید، «گفت‌وگوی تازه» بزنید و بپرسید «تعداد سفارش‌های شرکت چقدر است؟». بخش «تصمیم‌های ابزار و دادهٔ واقعی» نتیجه اصلی را نشان می‌دهد. ابزارها باید روشن باشند و دانلود مدل `qwen3:4b` که کاربر آغاز کرده تمام شده باشد. نبود مدل پیام `model_missing` می‌دهد و برنامه روشن می‌ماند.

```powershell
.\enterprise_agent\scripts\test.ps1 -Python 'D:\CompanyMicroApiTest\.venv\Scripts\python.exe'
```

پورت با `-Port` تغییر می‌کند؛ اگر اشغال باشد هیچ سرویس قبلی متوقف نمی‌شود. فقط یک worker اجرا کنید. مدل را با `OLLAMA_MODEL` عوض کنید؛ قابلیت‌های `completion` و `tools` از `/api/show` بررسی می‌شوند. اسم مدل نشانه تأیید قابلیت نیست. آزمون واقعی فارسی و ابزار برای هر مدل جدید لازم است.

## تنظیمات

فایل `backend/.env.example` خودکار خوانده نمی‌شود. در صورت نیاز یک کپی مستقل بسازید و با `-EnvFile` بدهید. متغیرهای موجود process نیز پشتیبانی می‌شوند.

| متغیر | پیش‌فرض / کاربرد |
|---|---|
| LLM_PROVIDER | ollama؛ adapter فعال فعلی |
| OLLAMA_BASE_URL | http://127.0.0.1:11434؛ فقط loopback |
| OLLAMA_MODEL | qwen3:4b؛ باید نصب کامل باشد |
| MCP_URL | http://127.0.0.1:8560/mcp؛ فقط loopback |
| MCP_ALLOWLIST | all_readonly؛ هر ۴۶ ابزار بازبینی‌شدهٔ فعلی؛ ابزار ناشناخته یا نوشتنی خودکار فعال نمی‌شود |
| LLM_CONTEXT | 4096 توکن در Ollama؛ بودجه ورودی محافظه‌کارانه برحسب نویسه است، tokenizer دقیق نیست |
| LLM_TEMPERATURE | 0 |
| LLM_TIMEOUT | 120 ثانیه برای درخواست مدل |
| RUN_TIMEOUT | 240 ثانیه برای کل اجرا |
| MAX_TOOL_STEPS | 6 فراخوانی؛ بین 1 و 12 |
| AGENT_API_TOKEN | اختیاری؛ shared secret توسعه، در فیلد توکن رابط وارد می‌شود |

## مرزهای نسخه فعلی

- تاریخچه در حافظه، با شناسه نشست HttpOnly و جداسازی مالک است؛ با restart پاک می‌شود. حداکثر 100 گفت‌وگو و ظرفیت محدود context؛ مناسب استفاده محلی تک‌کاربره.
- رابط وضعیت مدل، سرویس و ابزار را نشان می‌دهد. نتیجه متنی/ساختاریافته، جدول و نمودار میله‌ای ساده داده‌های عددی را بدون CDN یا اجرای HTML نمایش می‌دهد.
- فقط ابزارهای از پیش بازبینی‌شده خواندنی فعال می‌شوند؛ افزودن نام دلخواه به env کافی نیست. عملیات حساس/نوشتنی اصلاً اجرا نمی‌شوند؛ گردش تأیید و نقش‌های سازمانی هنوز فاز ۲ است.
- دریافت صوت WAV، MP3 و OGG از دکمهٔ ♫ کنار کادر پیام فعال است. پس از انتخاب فایل، می‌توانید پرامپت هم بنویسید؛ با زدن ارسال، Whisper متن فارسی را نمایش می‌دهد و متن همراه پرامپت به ایجنت می‌رود. TTS، vision و تولید تصویر هنوز قرارداد مستقل هستند.
- داده واقعی ابزار کنار پاسخ مدل نمایش داده می‌شود. متن مدل ممکن است اشتباه کند؛ برای تصمیم شرکت، شواهد ابزار و آزمون‌های دامنه ضروری است. واحد پول تنظیم‌نشده حدس زده نمی‌شود.
- نشست محلی و توکن اختیاری جایگزین احراز هویت سازمانی/RBAC نیست. این نسخه روی شبکه شرکت منتشر نشود.

جزئیات معماری، منابع رسمی و مسیر استقرار: [architecture.md](docs/architecture.md). نتیجه آزمون‌های این اجرا: [verification.md](docs/verification.md).

## ارسال فایل صوتی

دکمهٔ ♫ کنار کادر پیام را بزنید و فایل WAV، MP3 یا OGG انتخاب کنید. سپس پرامپت اختیاری بنویسید و ارسال را بزنید. فایل تبدیل و متن آن با پرامپت به ایجنت ارسال می‌شود؛ نیازی به نوشتن نام مدل یا ابزار نیست. ضبط مستقیم میکروفون و TTS هنوز اضافه نشده‌اند.

MobinAid از MCP stdio موجود در پوشهٔ هم‌سطح `WhisperMCP` و Python/مدل تعیین‌شده در config همان پروژه استفاده می‌کند؛ متغیر اختیاری `WHISPER_MCP_DIR` فقط مسیر آن پروژه را عوض می‌کند. هیچ مدل یا وابستگی تازه‌ای نصب نمی‌شود. metadata اتصال به معنی بارگذاری مدل نیست؛ بارگذاری هنگام نیاز انجام می‌شود. فایل موقت با نام تصادفی داخل پوشه مجاز Whisper ایجاد و در موفقیت، شکست یا لغو پاک می‌شود. سقف upload برابر 25MiB و مدت قابل پردازش تابع تنظیم فعلی Whisper (10 دقیقه) است. پسوند و header فایل بررسی می‌شوند و decoder موجود صحت صوت را کنترل می‌کند.

یک نشست MCP پایدار برای MobinAid حفظ می‌شود و worker آن در حافظه کافی بین درخواست‌ها قابل استفاده مجدد است؛ unload بیکار تابع تنظیم موجود 120 ثانیه است. mutex موجود Whisper مانع بارگذاری هم‌زمان موتور دوم می‌شود. اگر Bionic موتور جداگانه‌ای را فعال نگه داشته باشد، MobinAid همان حافظه را به‌زور تصاحب نمی‌کند و خطای مشغول‌بودن می‌دهد؛ اشتراک یک process زنده میان دو میزبان مستقل ادعا نمی‌شود.

در کمبود RAM، فقط مدل زبانی پیکربندی‌شده MobinAid با API رسمی Ollama موقتاً از RAM خارج می‌شود؛ فایل مدل حذف نمی‌شود. پس از STT، اگر برای بارگذاری LLM حافظه کافی نباشد، نشست Whisper بسته می‌شود تا مراحل متوالی اجرا شوند. برنامه‌های دیگر و مدل‌های میزبان دیگر خودکار بسته نمی‌شوند. اگر RAM حتی پس از این کار کافی نباشد، خطای واقعی نمایش داده می‌شود و متنی حدس زده نمی‌شود.

## گزارش دقیق مشتریان و خوانایی

گزارش رتبه‌بندی مشتریان یک شهر، با تعداد درخواستی و بیشترین مجموع مبلغ خرید، از فهرست customer_overview با limit کوچک حدس زده نمی‌شود. برنامه ابتدا business_semantics و روابط FK واقعی را می‌خواند، سپس با database_safe_join موجود، شهر و وضعیت پرداخت موفق را در سمت API فیلتر می‌کند. هر صفحه حداکثر 200 ردیف است؛ REPORT_MAX_PAGES پیش‌فرض30 و سقف مجاز50 است. تا پایان همه صفحات، رتبه‌بندی نهایی اعلام نمی‌شود. در این مسیر قطعی، حداکثر فراخوانی گزارش برابر REPORT_MAX_PAGES+2 است؛ سقف MAX_TOOL_STEPS مستقل برای حلقه انتخاب ابزار توسط مدل اعمال می‌شود. مهلت کل هر دو مسیر RUN_TIMEOUT است. هیچ SQL آزاد یا تغییر در API شرکت/دیتابیس انجام نمی‌شود.

تجمیع با Decimal بر اساس شناسه مشتری و شناسه یکتای سفارش انجام می‌شود؛ تکرار سفارش در JOIN یا صفحه‌بندی خطاست. مشتریان هم‌نام ادغام نمی‌شوند. واحد پول نامشخص حدس زده نمی‌شود. چون ابزار موجود snapshot تراکنشی مشترک میان صفحات نمی‌دهد، تغییر هم‌زمان داده می‌تواند روی سازگاری گزارش اثر بگذارد و این محدودیت در پاسخ ذکر می‌شود.

فونت B Nazanin موجود روی رایانه در رابط محلی استفاده شده است؛ هیچ فونتی دانلود یا نصب نشده است. متن پاسخ در دسکتاپ24px و نمای باریک23px است. جدول نهایی با DOM امن و textContent نمایش داده می‌شود؛ HTML خروجی مدل اجرا نمی‌شود. منابع چند فراخوانی در یک بخش جمع‌شونده قرار می‌گیرند و JSON ابزار ابتدا به ساختار واقعی تبدیل می‌شود تا رشته‌های escapeشده به عنوان پاسخ اصلی نمایش داده نشوند.

## نسخه اولیه محلی ایمیل و یادآوری

از دکمه «ایمیل و یادآوری» در بالای MobinAid استفاده کنید. یادآوری عنوان و زمان دقیق می‌گیرد، واقعاً در SQLite اختصاصی `data/workspace.sqlite3` ذخیره می‌شود و یک worker داخل سرویس هر2ثانیه موعدها را کنترل می‌کند. پنجره مرورگر هر3ثانیه وضعیت را می‌خواند و اعلان داخل صفحه نشان می‌دهد؛ این اعلان Telegram یا اعلان سیستم‌عامل نیست. «دیدم» وضعیت را تغییر می‌دهد. برای اثبات عملکرد، دکمهٔ آزمون واقعی10ثانیه‌ای وجود دارد.

داده یادآوری و ایمیل واردشده بعد از restart باقی می‌ماند و با شناسه همین مرورگر جدا می‌شود؛ کوکی نشست HttpOnly با عمر180روز است. پاک‌کردن کوکی یا مرورگر دیگر، هویت محلی دیگری ایجاد می‌کند و مکانیزم بازیابی حساب سازمانی در این نسخه وجود ندارد. این شناسایی، OIDC/RBAC سازمانی نیست. دیتابیس محلی رمزگذاری نشده و فایل EML واقعی شامل اطلاعات شخصی می‌تواند باشد؛ روی شبکه عمومی منتشر نشود. سقف1000یادآوری و500ایمیل برای نمونه محلی اعمال شده است.

ثبت یادآوری idempotency key دارد تا retry با همان اطلاعات دوباره ثبت نکند. زمان باید offset داشته باشد و UTC ذخیره می‌شود؛ فرم تاریخ میلادی با ساعت تهران +03:30 می‌گیرد. وقتی سرویس خاموش است، زمان‌بند اجرا نمی‌شود؛ در اجرای بعدی موارد عقب‌افتاده due می‌شوند. برای حفظ این قابلیت یک worker Uvicorn اجرا کنید. چت فعلاً صرفاً کاربر را به فرم ثبت واقعی راهنمایی می‌کند و ادعای ساخت یادآوری بدون ثبت نمی‌کند.

برای آزمون مسیر ایمیل، EML با بدنه متن ساده تا512KiB وارد کنید؛ از همان ایمیل می‌توان فرم یادآوری مرتبط را پر کرد. جست‌وجو واژه‌ای در subject/from/body و محدود به فایل‌های همین نشست است؛ پرسش‌وپاسخ معنایی روی صندوق Outlook هنوز فعال نیست. HTML و پیوست ایمیل اجرا نمی‌شوند. Outlook، Telegram و GPU شرکت در `/api/integrations` صریحاً not_configured هستند؛ قراردادهای آینده در `app/integrations.py` قرار دارند و پرکردن config به تنهایی این اتصال‌ها را فعال نمی‌کند. پیاده‌سازی adapter و احراز هویت واقعی مرحله بعد است. فعلاً هیچ رمز، توکن Telegram، حساب Outlook یا endpoint GPU لازم نیست.

مسیر پایگاه با `LOCAL_WORKSPACE_DB` قابل تنظیم است؛ این پایگاه از PostgreSQL شرکت مستقل است. هیچ جدول شرکت تغییر داده نمی‌شود و داده‌های این پوشه نباید commit شوند.
